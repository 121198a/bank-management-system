# Architecture decisions
**ADR-001 — Keep the stack; no rewrite.** Express/Mongoose/React/Vite retained; layering already sound. Rollback: n/a (additive).
**ADR-002 — Vite 8 + plugin-react 6 instead of `legacy-peer-deps`.** Makes `npm ci` deterministic in CI/Docker. Rollback: pin Vite 7 + plugin-react 4.
**ADR-003 — Visual redesign deferred.** Glass/gradient direction was added by the owner's earlier UI pass; kit says judge by context. Needs owner decision + browser-based responsive QA before restyling.
**ADR-004 — nodemailer 9 → 10.** Required to clear a high advisory; only `createTransport/sendMail` are used. Verified with jsonTransport only; **real SMTP not tested**. Rollback: `npm i nodemailer@9.1.1`.
**ADR-005 — No git history rewrite, no force-push.** Rotation recommended instead.
**ADR-006 — KYC encryption is opt-in and backward-compatible.** Legacy plaintext rows keep reading correctly; new/updated rows are encrypted only when a key is configured, so deploying the code cannot break existing data. Trade-offs: (1) partial-number search is lost when enabled (exact match via blind index instead); (2) key loss = data loss, so key backup is mandatory; (3) no key rotation yet (`enc:v1` prefix leaves room for a v2). Rollback: `npm run kyc:encrypt -- --rollback --apply` while the key is still available.
**ADR-007 — Redis rate limiting is opt-in with graceful degradation.** Fixed-window counting in one atomic Lua call. On Redis errors the limiter falls back to per-process counters (chosen over fail-open = no protection, and fail-closed = outage). Fixed windows allow up to 2x burst at a window boundary; acceptable for abuse control, not for billing. Compose Redis has no persistence by design.
**ADR-008 — API spec is generated, not hand-written.** Derived from the mounted middleware and validator chains so it cannot silently diverge; a test fails when it is stale. Trade-off: response schemas are not described (they are not declared in code). Adding response schemas would need explicit declarations per controller.
**ADR-009 — Own encrypted logical backup, alongside (not instead of) native snapshots.** Gives a portable, encrypted, verifiable copy with a safe restore path and no external binaries. Trade-off: not point-in-time consistent and unproven against a real database here; production should also use `mongodump --oplog` or provider snapshots. Uses `stream.pipeline` rather than readline because the latter hung on authentication failures (caught by tests).
